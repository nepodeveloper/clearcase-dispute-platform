# PR-11 — Concurrency-safe submission idempotency

**Batch:** Batch 03 — Financial reliability  
**Scope:** one PR only; do not start PR-12 automatically.  
**Outcome:** Guarantee safe replay of POST dispute requests with same idempotency key and body.

## Implement
Persist customer-scoped key + canonical payload fingerprint + response reference; PostgreSQL uniqueness; detect conflicting body; handle simultaneous submissions and eligible active-case uniqueness.

## Definition of accepted
- [ ] Same key+payload returns original case
- [ ] Same key+different payload 409
- [ ] Concurrent requests produce one case
- [ ] No duplicate active case per business rule

## Non-goals
No Kafka integration, generic idempotency framework or cross-bank transfer.
